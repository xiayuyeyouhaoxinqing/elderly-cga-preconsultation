# 门诊评估协助授权表设计

对应迁移 `20260826_outpatient_assistance`，代码实体 `backend/app/models/patient_assistance.py`。
本表只记录“谁在本次就诊被允许协助回答哪些内容”，不替代知情同意代签，也不参与计分。

## 表：patient_assistance_authorization

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| patient_id | BIGINT NOT NULL | 患者，外键 `patient.id` |
| encounter_id | BIGINT NOT NULL | 本次就诊，外键 `patient_encounter.id` |
| consent_record_id | BIGINT NULL | 授权时已同意的门诊评估同意记录，外键 `consent_record.id` |
| helper_name | VARCHAR(128) NOT NULL | 协助人姓名 |
| helper_relation | VARCHAR(64) NOT NULL | 关系，仅配偶、子女、父母、兄弟姐妹、其他亲属、照护者 |
| helper_contact_masked | VARCHAR(64) NULL | 联系方式掩码，仅保存末四位 |
| assist_scope | JSONB NOT NULL | 允许协助的采集范围编码列表 |
| status | VARCHAR(16) NOT NULL | active / revoked |
| authorized_at | TIMESTAMPTZ NOT NULL | 授权生效时间 |
| revoked_at | TIMESTAMPTZ NULL | 撤销时间 |
| revoke_reason | TEXT NULL | 撤销或替换原因 |
| recorded_by | VARCHAR(32) NOT NULL | 登记来源，如 patient:12 |
| creator / updator / create_time / update_time / deleted | 通用业务字段 | 见《数据库表业务设计.md》统一字段规范 |

索引：`idx_assistance_authorization_encounter (encounter_id, status, deleted)`、
`idx_assistance_authorization_patient (patient_id, encounter_id, deleted)`。

## 约束与流转

- 一个就诊最多一条 `status=active` 记录，由服务层在写入时先撤销旧记录再插入，数据库不建部分唯一索引，
  以保留完整历史。
- 授权前必须存在本次任务已完成的门诊评估同意记录；门诊状态不是“门诊评估中”时拒绝写入。
- `assist_scope` 只接受固定编码；认知（B.8）、谵妄（B.21）、体能现场测试（B.3）及专业观察项目（
  B.12、B.15、B.16、B.17、B.20）不在允许集合内。
- 撤销即改 `status`、`revoked_at`、`revoke_reason`，不物理删除。

## 与其他表的关系

- `assessment_submission.submitter_type` 与 `assessment_answer.value_source` 是后续写入协助作答来源的位置；
  本分支只登记授权事实，尚未改写这两处。
- `consent_authorization` 记录家属代为签署同意书的授权，与本表并行，互不覆盖。
