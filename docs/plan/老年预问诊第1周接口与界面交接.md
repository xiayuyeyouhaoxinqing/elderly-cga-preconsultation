# 老年预问诊第1周接口与界面交接

## 页面与设计

界面参考诊室指引牌和纸质量表。沿用现有暖白底和深色文字，深橙强调主操作。首屏只分患者、职工两个入口。患者样板逐题展示，大字模式放大题目与选项，使用文字显示进度和状态。职工登录去掉无操作的人脸识别占位，按“工号、密码、登录”排列。

| 页面 | 本周状态 |
| --- | --- |
| `/` | 双身份入口，Mock 下另有样板入口 |
| `/nurse/login` → `/nurse/dashboard` → `/nurse/scales` | 复用职工登录、会话和量表查询。演示账号按钮限 Mock |
| `/patient` → `/patient/tasks` | 现有患者入口，API 当前适用于住院患者，门诊身份和会话在第2周改造 |
| `/patient/assessment-preview` | Mock 模式可打开，B.1 与 B.2 各一题，支持返回修改、放大及报告草稿预览。作答只在当前页面内存中 |
| 医护采集、医生审核和签署 | 后续新增或适配。审核页优先展示待核验项，再展示来源、原始答案、结果及限制，签署按权限控制 |

## 接口联调与数据契约草案

- 职工继续使用 `POST /api/auth/staff/login` 及职工 HttpOnly Cookie，量表查询为 `GET /api/scales`。患者继续使用 `POST /api/patients/login` 及独立患者 Cookie。第2周须同时适配患者登录、会话校验及本人任务查询。
- 收到上传接口后核对请求结构、工具标识、标准来源、版本号、状态、有效期、重复导入行为及错误码。拟验收状态为草稿 → 待临床确认 → 已发布 → 已停用。新任务绑定发布时的版本，旧任务保留原版。路径、枚举及数据库迁移待按实际分支对齐。
- 报告草稿字段草案包括本次就诊标识、评估批次、工具及版本、采集来源、原始答案或测量引用、核验状态、结果或限制。报告按已复核结果生成。样板只验证呈现及交互，没有调用报告 API。
- 隔离联调需准备 PostgreSQL、Redis、职工测试账号、合成门诊病例。真实环境的上传 → 临床审批 → 发布 → 查询留待合并接口后执行。

## 本周可复现的验证

- 前端使用 Node 22.12.0、pnpm 10.26.2，执行 `pnpm check`。74 个测试通过，Lint、类型检查及构建通过。
- 在 `backend` 执行 `uv run pytest tests/unit-test/test_staff_auth.py tests/unit-test/test_scale_list.py tests/integ-test/test_scale_list_sqlite.py -q`，10 项通过。认证链路覆盖错误密码、仅患者 Cookie 时拒绝访问、职工登录、HttpOnly 会话、仅查询生效已发布记录、退出后拒绝访问。基础设施为隔离 SQLite 与内存会话。
- 后端常规单元套件已尝试，98 项通过后在既有 `test_publish_dialog_turn_event` 停止。本机 Redis 6379 拒绝连接，造成该项失败及清理错误。小组环境需重新执行全套。
- 在 `frontend` 设置 `NEXT_PUBLIC_DATA_MODE=mock` 后执行 `pnpm dev --port 3013`，从首页分别走患者和职工入口。桌面用演示账号进入量表列表。390px 下验证大字模式、必选项提示、样板结果与返回修改，浏览器无控制台错误。切换 API 模式后，首页与登录页隐藏演示入口，样板直达地址显示未找到页面。
